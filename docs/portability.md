# 迁移与数据存储

## 到另一台 Windows 电脑

1. 只复制／下载完整的 Windows x64 发布 ZIP，解压到可写目录。
2. 启动 `BrowserControl.exe`，直接进入主界面。无需安装 Python、Node.js 或 npm。
3. 重新加载该电脑浏览器中的 `extension` 文件夹，复制新配对码完成配对。
4. 在面板“接入 AI”中生成该电脑的 MCP／DSH 配置。

不要复制旧电脑的用户数据目录、配对密钥、浏览器配置或 AI 客户端凭据。程序沿用的是目标浏览器自己的登录状态，不迁移登录信息。

## 同一电脑换目录或升级

使用 Windows `*-setup.exe` 时，安装器会先查找已安装的程序，并在安装前显示可编辑的目标目录。检测到旧版时默认选中原目录，否则默认使用 `%APPDATA%/BrowserControl`。未检测到旧的便携版时，可以手动选择它的程序目录。升级前在旧面板点击“断开”，并关闭旧面板和 AI 客户端。

同目录升级会替换程序文件，保留原数据目录和程序旁的 `.local`。选新目录会保留旧安装并沿用原数据位置。在新面板连接服务后，按需要重新加载浏览器扩展并重启 AI 客户端。若原数据存放在旧程序目录内，先在面板中迁移数据，再清理旧目录。

先断开并关闭旧程序，再解压新包、打开新位置的面板。默认目录保持不变；若之前自定义过目录，升级前保留程序旁 `.local/storage-location.json`，新版本继续使用原位置。也可在首次运行新包前执行 `node scripts/paths.mjs --select <原数据目录>` 复用原数据。点击“连接”会更新固定 MCP 启动入口；浏览器中未打包扩展的目录需要重新选择／加载。重启 AI 客户端，让已经运行的 MCP 进程加载新位置。

若运行环境的 Node.js 版本也升级，AI 客户端可能正在占用数据目录中的旧 Node.js。先关闭使用该 MCP 的客户端再升级，然后重新打开。版本升级时不要同时运行旧包和新包。

## 数据位置

启动时自动使用本机默认数据目录，不弹出目录选择窗口。Windows 默认 `%LOCALAPPDATA%/BrowserControl`，macOS 默认 `~/Library/Application Support/BrowserControl`，Linux 默认 `${XDG_STATE_HOME:-~/.local/state}/browser-control`。C 盘与其他可写磁盘均可使用。默认位置不可写时，使用程序内 `.local/state` 并在界面显示，可从设置更改。

当前数据目录内包括 `settings.json`、每端口配对密钥、AI 接入实例记录与身份令牌（`ai-instances.json`、`ai-token-*.json`、`identity-*.json`，权限 0600）、断开标记、日志、固定 MCP 启动器、本地 Node.js 副本、客户端配置备份和按需生成的 DSH 插件。它们都是运行时数据，未纳入源码或发布包。自定义位置记录在程序旁 `.local/storage-location.json`，迁移到其他电脑后使用该电脑的默认位置。

面板“设置 → 更改存储位置”会迁移旧数据：先断开使用旧目录的服务，复制缓存、日志、密钥和设置，逐文件校验后保存新位置，再清理旧文件。浏览器配对和端口保留；生成的 DSH 插件会更新内部路径。AI 客户端原配置中的绝对路径需要从“接入 AI”重新导入，随后重启客户端。

请先关闭正在使用这些工具的 AI 客户端，再迁移。取消选择不改变目录或连接状态；目标非空、目录重叠、包含目录链接或校验失败时不切换位置、不删除原数据。如果旧文件被占用或迁移时发生变化，程序会保留无法清理的文件并明确显示旧位置。

卸载时先断开、关闭使用 MCP 的 AI 客户端，移除客户端中的接入配置和浏览器扩展，再删除程序文件夹及当前的数据目录。

浏览器原有用户配置、扩展在浏览器内的配对设置及 AI 客户端自身的配置文件仍由各应用管理；“添加本地工具配置”会写入 AI 客户端已有的配置位置。

源码可直接执行 `npm start`。首次配置可用 `node scripts/paths.mjs --select <数据目录>`；使用后迁移请用面板入口或 `node scripts/cli.mjs migrate-storage <新目录>`。`BROWSER_CONTROL_DATA_DIR` 可指定隔离位置；`BROWSER_BRIDGE_PORT` 可覆盖端口。自定义数据目录不会自动被发布脚本收集。

## 跨系统

Windows `.exe` 只能在 Windows 上运行。macOS/Linux 使用源代码与该系统的 Node.js 22+；Chrome/Chromium 扩展代码共用。Python GUI 源码提供跨系统打开文件与数据路径，但本次未在 macOS/Linux 实机验证 GUI。不要把 Windows 的 `runtime/node.exe` 当作其他系统的运行时。

## 常见问题

- **端口被旧版占用**：先断开旧版，或面板“设置”选择其他端口，再重新配对。
- **AI 没有工具**：确认客户端支持本地 stdio MCP、配置已经加载；重启客户端并新建本地会话。
- **扩展已连接但不能操作**：浏览器中要授权当前标签页，且控制不能处于暂停状态。
- **移动后扩展打不开**：重新加载新目录中的未打包扩展。
- **只复制 exe 后提示缺文件**：重新解压完整发布 ZIP。便携包不是单个独立 exe。
- **Windows 下载提示未知发布者**：本地构建暂未做代码签名。维护者可为正式发布添加签名；校验 ZIP 的 SHA-256，勿将未知来源文件当作官方发布。
