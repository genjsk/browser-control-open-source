# AI 客户端接入

所有接入方式都只连接控制面板管理的同一个本地服务。客户端可以启动自己的 stdio MCP 接入进程，但该进程只转发请求，**不会**启动后台桥接服务、创建监听端口或启动第二份服务。服务未运行时，工具调用会返回“本地服务未启动”，请打开 Browser Control 控制面板并点击“连接”。

## 逐次校验与实例身份

每类接入使用稳定且独立的实例身份（通用 MCP、Codex MCP、Codex 原生插件、DSH 各一个）。身份令牌只保存在本机数据目录（文件权限 0600），不会写入源码、插件模板或发布包。每次工具调用前，本地服务都会核对：

- 实例身份有效，且该实例未被暂停；
- 插件配置的端口与当前服务端口一致；
- 配对凭据属于该端口，浏览器扩展连接到该服务；
- 本地服务仍在运行。

核对失败时不会执行浏览器操作，并返回插件配置端口、当前服务端口和失败原因。成功时工具结果包含 `verification`（`portMatches`、`pairing: "verified"`、`browserConnected` 等）。返回内容和日志都不包含配对码、配对密钥或网页内容。

常见诊断：

| 结果码 | 含义 |
| --- | --- |
| `SERVICE_NOT_RUNNING` | 本地服务未启动，需在控制面板点击“连接” |
| `PORT_MISMATCH` | 插件配置端口与当前服务端口不一致 |
| `PORT_OCCUPIED` | 端口上存在其他程序或其他 Browser Control 实例 |
| `PAIRING_MISMATCH` | 配对凭据与当前端口或服务身份不匹配 |
| `INSTANCE_PAUSED` | 该 AI 接入实例已被暂停 |
| `EXTENSION_DISCONNECTED` | 浏览器扩展未连接或连接已断开 |

控制面板“AI 接入情况”会显示每个实例的状态（已安装、在线、离线、已暂停）和最近调用时间，并可单独暂停或恢复。暂停由服务端强制执行，其他实例不受影响；暂停状态会保存，并在实例重新连接后继续生效。关闭客户端后，实例会在心跳过期后显示为离线。

## 通用 MCP

在面板中选择“接入 AI → 复制 MCP JSON”。将生成的 `mcpServers.browser_control` 项添加到支持本地 stdio MCP 的客户端。生成配置包含本机用户数据目录中的 Node.js 和固定启动器路径；这些路径按目标电脑生成，不应复制到另一台电脑。

固定启动器读取同目录内的 `runtime.json`，再从当前程序目录加载 MCP 服务。每次面板连接／生成接入配置时都会更新程序位置。因此同一电脑迁移程序目录后，客户端无需手动追踪原安装目录。

源码模式也可以使用 `node` 运行仓库的 `bridge/entry.mjs`，使用默认或已保存的数据目录；这需要目标电脑已有 Node.js，并在移动仓库后手动更新配置。

## GPT / Codex

推荐使用面板“接入 AI → 安装到 Codex”，直接安装包含浏览器工具和操作指引的原生插件。exe、本地服务和 DSH 接入继续保留。完整说明见 [Codex 原生插件](codex-plugin.md)。

面板“旧版 MCP 配置接入”面向读取 `.codex/config.toml` 的本地执行客户端。安装器先验证 TOML 语法，在所选数据目录的 `client-config-backups` 下备份已有配置，保留其他配置和注释，只管理自己带标记的 `browser_control` 小节。客户端配置本身仍写入该客户端已有的位置。

如果已有另一个同名服务器，安装器不会覆盖它。请先移除旧版同名配置，或通过客户端的 MCP 表单手动导入 JSON。已有会话通常需要重启／新建会话才能获得新工具。

这不保证所有 ChatGPT 普通聊天窗口、账号或组织策略都允许本地工具。只支持远程 HTTPS MCP 的客户端无法直接使用本项目的 stdio 服务。

## DeepSeek Harness

面板“生成 DSH 插件”在当前用户数据目录生成一个有效的 Cordis bundle，并提供本机安装命令。可以在 DSH 添加本地插件，或运行生成的 `dsh plugin --profile web add ...` 命令。插件通过官方 `@deepseek-ai/dsh-mcp-client` 暴露 11 个工具。

生成后点击“复制插件地址”（在“打开插件目录”上方），将文件夹路径直接粘贴到 DSH 添加本地插件的位置即可。

安装至其他 profile 时修改命令中的 profile 名称。独立 DSH Desktop profile 应通过该桌面客户端自己的插件管理入口安装；npm CLI 不负责管理它。

同名插件已安装时先在 DSH 中更新／移除旧版，不要重复注册同一个服务器名称。停用 DSH bundle 只卸载 DSH 的连接，不移除浏览器扩展或 GPT 配置。

截图是否能被模型理解取决于该模型与 DSH 的附件能力；不能接收图像的模型仍可使用正文和元素快照。两个 AI 共用服务时，请避免同时操作同一页面。

## DSH 与模型平台限制

本插件和本地服务不设置累计操作次数、每会话调用次数、每日配额或固定最大操作轮数，AI 可以持续调用直到任务完成、用户停止、服务断开或实例被暂停。需要区分以下两类限制：

- **可由本插件控制**：单次工具调用超时（DSH bundle 默认 `toolCallTimeoutMs: 40000`，本地服务默认 12 秒、上限 30 秒）、断线处理和超时不重放。这些是防止单个请求永久挂起的保护，不是次数限制，可按需调整。
- **由 DSH 或模型平台强制、本插件无法取消**：模型请求超时、上下文窗口、最大输出长度、并发或账号额度，以及 DSH goal 的自动续行轮数（`dsh-goal` 的 `defaultMaxGoalRounds` 默认 256，属于部署配置，不是浏览器工具次数）。DSH 默认没有按轮次的工具调用预算；如果安装了额外预算插件或在部署中设置了上限，需要在 DSH 侧调整。插件不会也不能绕过这些限制。

如果客户端仍出现“达到最大轮数”一类提示，请检查 DSH 配置、goal 设置或所安装的预算插件，而不是浏览器控制插件。
